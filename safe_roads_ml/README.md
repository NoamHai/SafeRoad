# Safe Roads ML: setup and running scripts

`final_model/training/train_final_model.py` trains and exports the final binary
HistGradientBoosting model used by the backend. The binary model comparison,
feature ranking, and EDA are supporting experiments. `model_trials/previous/`
and the mentor examples are historical work, not required steps before final training.

## Environment

Use a dedicated Python environment. From the project root, install:

```powershell
python -m pip install -r safe_roads_ml/requirements-ml.txt
```

The project documents Python 3.10+. Use an interpreter supported by the listed
packages. Shared pandas, scikit-learn, and joblib constraints match the application
requirements; the ML list does not install the web framework. Other dependencies
are unpinned because their historical versions are unknown. Installation and
runtime compatibility have not been verified; this is not a reproducibility lockfile.

## Run requirements

Commands below are instructions, not a sequence to run. Activate your environment,
start at the project root, then `cd` into the listed working directory before
running its command. Paths are relative to the working directory unless stated
otherwise. All listed inputs and the final output directories exist in the
inspected checkout. No earlier workflow needs rerunning to use those inputs.

The prepared Excel inputs already exist but are **not generated by the inspected
scripts**; their preparation process is not documented here. Use each script's
local input copy. `data/raw/accidents_raw_master.csv` and
`docs/mentor/files_from_iyad/accidents_raw_master.csv` are separate copies:
running the merger does not update the mentor copy.

The comparison scripts create `runs/` when needed. Their timestamps use
`YYYYMMDD_HHMMSS`: a new timestamp normally creates new files, but an identical
timestamp can overwrite matching files. Fixed-name outputs overwrite existing
files. The final trainer does not create its output directories.

Relative paths are intentional: running from a different directory can fail to
find inputs or write outputs elsewhere. Several scripts execute work on import;
do not import them just to inspect their functions.

These instructions were checked against source code and file locations only.
No ML workflows were run and no results were regenerated during this cleanup.
